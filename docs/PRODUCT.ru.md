# quant-memcoins-researcher: что это и что умеет

## Коротко

Это исследовательский цикл для поиска торговых стратегий на мемкоинах Solana. Claude предлагает гипотезы, критик их отсеивает, код проверяется в песочнице, а результат оценивается так же строго, как в хедж-фонде: с честным учётом числа попыток, издержек, рагов и рыночной беты.

## Что умеет

- **Вселенная без выживших** (`TokenPanel`, `geckoterminal.py`). Пул попадает в базу в момент появления и остаётся в ней навсегда, даже после смерти. Иначе бэктест видит только монеты, у которых ещё есть график, то есть только победителей.
- **Раг списывается в ноль** (`meme_backtest`). Если цена пропала, пока позиция открыта, вся позиция пропадает. На мемкоинах это главный источник потерь, и выбрасывать такие монеты из выборки было бы самообманом.
- **Точные издержки AMM** (`amm.py`). Потеря на кривой x·y=k считается по формуле `1 − (1−f)·Q/(Q+s)`, к ней добавляются priority fee и потери на MEV. В пуле на $20k размер сделки решает всё, а фиксированная ставка в бипсах тут не работает.
- **Бэктест в долларах, а не в весах.** Только лонг, исполнение со сдвигом на бар, лимит на долю в пуле, минимальная ликвидность для входа, зона без ребаланса. Одна и та же стратегия на $1k и на $1M — это две разные стратегии.
- **Ёмкость** (`capacity_curve`, `estimate_capacity`). Те же веса прогоняются на суммах от $1k до $1M. Видно, при каком размере книги доходность исчезает.
- **Мем-факторы и атрибуция** (`factors.py`): MKT, SIZE, MOM, AGE, FLOW, раги учтены как −100%. Так видно, где альфа, а где просто ставка на общую манию.
- **Deflated Sharpe с учётом всех попыток.** Лучшая из 20 стратегий почти всегда выглядит хорошо, и тест штрафует за перебор.
- **Тиршит одной командой** (`tear_sheet`). Он показывает доход после издержек, раскладку издержек, списания на рагах, ёмкость, Sharpe по половинам выборки, беты, t-статистику альфы и DSR.
- **Синтетический рынок** (`simulate.py`). В нём есть запуски, раги в первый час, утечка ликвидности и общий цикл внимания. «Нулевая» лента (без преимущества) проверяет, что фильтры отсекают то, что должны.
- **Поля токена из GeckoTerminal**: холдеры, доля топ-10 кошельков, mint/freeze authority, прогресс кривой pump.fun. Всё это хранится point-in-time: значение известно только с момента наблюдения.
- **Готовые фичи для стратегий** (`features.py`): ликвидность, возраст, моментум, приток ликвидности, объём, рост холдеров, `rug_screen`, `graduation_window`, ранги, top-N.
- **Цикл Claude под мемкоины**: отдельные промпты для гипотез, критика и кода. Стратегия имеет вид `strategy(panel) -> weights` и выполняется в песочнице со строгим списком разрешённых импортов.

## Как запустить

```bash
python -m ai_quant_lab.meme demo                        # синтетика, без ключа и данных, ~1 мин
python -m ai_quant_lab.meme run --db data/meme.db       # сборщик: снимки + токены + свечи, без остановки
python -m ai_quant_lab.meme info --db data/meme.db      # что накоплено в базе
python -m ai_quant_lab.meme research --db data/meme.db --iterations 20   # нужен ANTHROPIC_API_KEY
```

Есть и отдельные команды: `collect` (только снимки) и `backfill` (5-минутные свечи по всем пулам).

## Что показало демо

- На ленте без преимущества все 20 вариантов стратегии теряют деньги. Так и должно быть.
- На ленте с заложенным преимуществом в плюсе 12 из 20. Лучший вариант (+127%, Sharpe 5.7) всё равно отклонён: первая половина выборки отрицательная, β к мем-рынку 0.29, t-статистика альфы −0.73, DSR p=0.71. Инструмент поймал, что прибыль пришла от рыночной беты.
- По ходу нашли и исправили две ошибки. Исходная песочница на деле не давала импортировать библиотеку фич. Генератор синтетики без поправки −σ²/2 показывал +1604% на нулевой ленте.

## Что добавлено в последнем обновлении

- Из GeckoTerminal теперь собираются число холдеров, доля топ-10 кошельков, mint/freeze authority и прогресс кривой pump.fun. Они попадают в панель point-in-time: до первого наблюдения там NaN.
- Новая фича `rug_screen` отсекает токены, где создатель ещё может минтить или замораживать, а также токены, где топ-10 держат больше половины эмиссии. Если поле ещё не наблюдалось, это считается провалом проверки.
- Новая фича `graduation_window` отмечает токены, у которых кривая заполнена на 70–100%, то есть близкие к переезду в настоящий пул.
- Команда `run` объединяет всё в один процесс сборщика: новые пулы, снимки, токены и обновление свечей у 15 самых устаревших пулов. Все запросы делят общий лимит API (~30 в минуту).
- Модель по умолчанию теперь `claude-opus-5-5`. Новым моделям `temperature` больше не передаётся.
- Живая проверка: сборщик работает с бесплатным API GeckoTerminal (пулы pump.fun, PumpSwap, Meteora), поля токенов доходят до панели. Проходят 136 тестов.

## Ограничения

- Реальной истории пока нет. Чтобы исследовать на настоящих данных, базу нужно копить днями или неделями.
- Постоянный фоновый сбор ещё не запущен. Шаблон launchd есть (`deploy/com.quantmeme.collector.plist`), но без Full Disk Access launchd не видит внешний диск. Решение за владельцем: выдать доступ или перенести проект на внутренний диск.
- GeckoTerminal заполняет число холдеров с задержкой: у свежих токенов его какое-то время нет.
- Значения комиссий в `ExecutionCosts` — заглушки. Их нужно выставить по реальной площадке.
- Для цикла с Claude нужен `ANTHROPIC_API_KEY`.
- Это инструмент исследования, а не торговый бот. Транзакций он не отправляет.

## Разумный следующий шаг

Запустить `run` в фоне: выдать Full Disk Access или перенести базу на внутренний диск. Дать ему накопить хотя бы 1–2 недели данных. Параллельно выставить комиссии в `ExecutionCosts` по реальной площадке. Потом прогнать `research` на собранной базе и смотреть тиршит лучших кандидатов в таком порядке: издержки на доллар оборота, Sharpe по половинам выборки, бета и альфа, ёмкость, DSR.
